# ADR 0005 — Content as Data, Assets Referenced by ID

Status: Approved (Phase 1).

## Decision

1. All story content (scenes, hotspots, dialogue, evidence, journal
   entries, deductions, characters) lives as JSON under `/src/content`,
   typed against `src/engine/types.ts`. Engine code never contains story
   text, character names, or scene-specific logic.
2. Every visual/audio asset is referenced everywhere — in content JSON
   and in engine code — by an opaque **asset ID** (`AssetId = string`),
   never by a file path. `BackgroundManager`, `PortraitManager`,
   `EvidenceSystem`, and `AudioManager` all take asset IDs and treat them
   as Phaser texture/audio keys.
3. In Phase 1, asset IDs resolve to **programmatically generated
   placeholder textures/audio** (`src/engine/placeholder/`), registered
   by `PlaceholderAssetLoader` from `/src/content/placeholderAssets.json`.
   No art or final audio is generated by Claude, per the Phase 1
   constraint — placeholders are flat-color panels with a baked-in
   "PLACEHOLDER" label (textures) or a synthesized beep (SFX only).

## Rationale

This is the concrete implementation of `docs/CLAUDE.md`'s mandate to
"keep story content external to the engine" and "load dialogue, scenes,
evidence, and choices from data files," plus the approved Phase 1
instruction that "assets should be referenced by IDs in content data
rather than hardcoded paths throughout the engine."

## Consequences — how to swap in final art

When final art/audio arrives, only the asset-resolution layer changes:

- Replace `PlaceholderAssetLoader`'s data source
  (`placeholderAssets.json` + the canvas-drawing factory) with a loader
  that maps the same asset IDs to real file paths and calls Phaser's
  normal `this.load.image(...)`/`this.load.audio(...)`.
- `SceneManager`, `BackgroundManager`, `PortraitManager`,
  `EvidenceSystem`, `AudioManager`, and every content JSON file are
  untouched — they only ever knew the asset ID, never the fact that it
  was a placeholder.
- Every placeholder definition (`CharacterDefinition`, `SceneDefinition`,
  `EvidenceDefinition`, etc.) carries a `placeholder: boolean` flag
  independent of the asset system — this drives the visible "Placeholder"
  badges in DOM UI (`src/ui/dom.ts`'s `placeholderBadge()`) so Phase 1
  test content can never be mistaken for canon, per the explicit
  instruction to label all placeholder content clearly.
